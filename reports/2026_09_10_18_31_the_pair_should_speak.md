# 단어쌍은 다른 페이지가 아니라 소리를 열어야 한다

## 예문 아래의 작은 사전을 걷어 내고, 화면에 적힌 독일어 표현을 그대로 들려준다. 새로 필요한 것은 14,850개 파일이 아니라 중복을 뺀 2,510개다

2026년 9월 10일 오후 6시 31분 | 11 min read

*Heute / 오늘*을 누른다. 지금 앱은 *heute*라는 단어의 상세 화면으로 간다. 이것은 틀린 동작은 아니다. 그러나 방금 읽던 예문은 사라지고, 학습자는 이미 눈앞에 있던 뜻을 더 큰 카드에서 한 번 더 본다. 작은 밑줄은 사전으로 가는 문처럼 보이지만 그 문 뒤에 새로 얻을 정보가 별로 없다.

그 자리에 아직 없는 정보는 소리다. *habe / 가지고 있다*를 보면서 궁금한 것은 이 활용형이 사전에서 *haben* 아래에 들어간다는 사실보다, 화면에 적힌 *habe*가 실제로 어떻게 들리는가다. 따라서 단어쌍을 누르면 상세 화면으로 이동하지 않고 그 쌍의 독일어를 한 번 읽게 하는 편이 낫다. 문장 왼쪽의 재생 버튼은 문장 전체를 계속 읽는다. 둘은 경쟁하는 기능이 아니라 확대 배율이 다른 듣기다.

```
문장 재생 ▶  Heute kann ich nicht kommen, aber morgen habe ich Zeit.
               └─ 전체 문장의 리듬과 억양

쌍을 누름     habe
              가지고 있다
               └─ 지금 보고 있는 표현 하나의 발음
```

이 변화에는 MP3가 필요하다. 다만 “화면의 모든 쌍마다 파일 하나”라고 곧이곧대로 만들면 같은 *ich*를 642번 합성한다. 화면의 쌍과 디스크의 파일은 일대일일 필요가 없다. 같은 독일어 표현은 같은 파일을 가리키면 된다.

## 이미 있는 단어 소리는 절반만 맞는다

이 저장소에는 오디오 공장이 이미 있다. `07_audio.py`는 단어 3,005개의 `lemma`와 예문 6,417개의 `de`를 Piper에 넣고, id를 파일명으로 삼는다. 현재 만들어 둔 A1 오디오는 단어 679개와 문장 2,585개, 모두 3,264개다. 실제 파일 크기는 36,284,386바이트다.

```python
for word in words:
    yield word["id"], word["lemma"], (word_scale, slow)

for sentence in sentences:
    yield sentence["id"], sentence["de"], (sentence_scale,)
```

단어 카드에서는 이것으로 충분하다. 카드가 *haben*을 보여 주고 파일도 *haben*을 읽기 때문이다. 예문의 쌍에서는 그렇지 않다.

| 화면에 적힌 표현 | 연결되는 표제어 | 기존 단어 MP3가 읽는 것 |
|---|---|---|
| `habe` | `haben` | `haben` |
| `muss` | `müssen` | `müssen` |
| `geht es` | 하나로 정할 수 없음 | 해당 파일 없음 |
| `im Büro` | 둘 이상의 표제어 | 해당 파일 없음 |

기존 파일을 재사용하면 버튼은 *habe*라고 쓰여 있는데 스피커는 *haben*이라고 말한다. 발음 확인 장치로서는 작은 차이가 아니라 계약 위반이다. 여러 낱말을 한 뜻으로 묶은 쌍은 어느 사전 id를 골라도 해결되지 않는다. 새 오디오는 표제어가 아니라 `glossParts()`가 화면에 꺼내 놓는 독일어 범위를 읽어야 한다.

한국어까지 합성할 필요는 없다. 이 쌍에서 한국어는 무엇을 읽고 있는지 알려 주는 자막이고, 발음의 대상은 독일어다. 한 번의 탭에 독일어와 한국어를 차례로 읽으면 짧은 예문을 훑는 속도가 오히려 느려진다.

## 14,850쌍을 2,510개 파일로 줄인다

현재 문맥 주석이 완성된 A1 예문은 2,427개다. 그 안에는 화면에 그려질 쌍이 14,850개 있다. 주석이 소비한 독일어 토큰만 공백으로 이은 뒤 철자가 정확히 같은 표현을 합치면 고유한 독일어 발화는 2,510개만 남는다. 즉 논리적인 쌍 여섯 개 가운데 다섯 개는 이미 다른 쌍과 같은 MP3를 쓸 수 있다.

| A1 현재 데이터 | 개수 |
|---|---:|
| 전체 예문 | 2,585 |
| 문맥 주석이 있는 예문 | 2,427 |
| 화면에 나타나는 단어쌍 | 14,850 |
| 중복을 뺀 발음 문자열 | 2,510 |
| 그중 여러 낱말인 문자열 | 267 |

중복 제거에서 대소문자를 없애면 고유 문자열은 2,277개까지 더 줄어든다. 이 233개 절약은 하지 않는 것이 좋다. 독일어의 *Weg*는 길이고 *weg*는 사라졌다는 뜻이며 발음도 `/veːk/`와 `/vɛk/`로 다르다. 저장 공간 몇 MB보다 잘못된 소리 한 번이 더 비싸다. 유니코드는 NFC로 맞추고 공백은 정리하되, 대소문자와 내부 철자는 보존해야 한다.

발음 문자열은 화면 조각을 대충 다시 자르지 않고, 주석이 소비한 토큰 범위에서 한 번만 만든다. 예컨대 마지막 쌍의 화면 표기는 `Zeit.`여도 Piper에 보낼 값은 `Zeit`다. `geht es`처럼 주석 하나가 낱말 둘을 소비하면 둘을 함께 보낸다. 쉼표가 쌍의 경계에 걸려 들어가 같은 단어의 파일을 둘로 만드는 일도 막는다.

```python
def spoken_gloss(text: str, matches: list[re.Match], start: int, span: int) -> str:
    """주석 한 쌍이 소비한 독일어 토큰만 발음 문자열로 만든다."""
    return " ".join(match.group(0) for match in matches[start:start + span])
```

이 함수와 토큰 정규식은 파이프라인과 브라우저가 각자 복사해서 가져서는 안 된다. 지금도 Python의 `GLOSS_TOKEN_RE`와 TypeScript의 `GLOSS_TOKEN_RE`가 따로 있다. 오디오 id까지 양쪽에서 계산하게 만들면 어느 날 괄호나 숫자 처리 하나가 달라져 화면에는 존재하지만 파일은 없는 버튼이 생긴다. **Python이 최종 발음 문자열과 id를 확정하고, 브라우저는 받은 id만 재생해야 한다.**

## 파일명은 문장이 아니라 발음 내용에서 나온다

문장 id를 빌려 `문장id-쌍번호.mp3`로 만들 수는 있다. 구현은 쉽지만 *ich*가 등장한 문장 수만큼 파일이 생기고, 주석 경계 하나를 고치면 그 뒤의 번호가 모두 다른 뜻을 갖는다. 발음 문자열의 내용 해시가 더 안정적이다.

```python
def gloss_audio_id(spoken: str, profile: str = "thorsten-high_1.25_32k_v1") -> str:
    payload = f"{profile}\0{spoken}".encode("utf-8")
    return "g" + hashlib.sha256(payload).hexdigest()[:12]
```

음성 모델, 속도, 비트레이트를 `profile`에 넣는 이유가 있다. 지금 서비스 워커는 같은 파일명의 MP3 내용이 바뀌면 캐시 번호를 사람이 올려야 한다. 내용에 렌더링 설정까지 포함하면 소리를 다시 만들었을 때 URL도 바뀐다. 오래된 브라우저가 새 화면에 옛 발음을 붙이는 일을 구조적으로 없앤다. 12자리 해시는 현재 규모에 넉넉하지만, 생성할 때 `id → spoken` 역색인을 만들어 충돌하면 즉시 실패시키는 검사는 남겨야 한다.

파일은 기존 단어·문장 오디오와 섞지 않고 아래에 둔다.

```text
construct_dataset/data/audio/
├── haben.mp3                 # 단어 카드: 표제어를 두 속도로 읽음
├── s9f….mp3                  # 예문 버튼: 문장 전체를 한 번 읽음
└── gloss/
    ├── g12자리해시.mp3       # 단어쌍: 화면의 독일어 표현을 한 번 읽음
    └── …
```

분리된 디렉터리는 단지 보기 좋으라고 만든 것이 아니다. `--only glosses`로 쌍 발음만 다시 만들 수 있고, 사이트로 옮길 때 현재 등급이 참조하는 파일만 고를 수 있으며, 고아 파일을 찾을 때 단어와 문장 오디오를 건드리지 않아도 된다.

## 데이터에는 소리의 주소를 쌍과 함께 싣는다

현재 앱 데이터의 주석은 `[낱말 수, 한국어 뜻]` 두 칸이다.

```json
"g": [[1, "오늘"], [1, "~할 수 있다"], [1, "나는"]]
```

여기에 발음 id를 세 번째 칸으로 넣는 것이 가장 작은 변화다.

```json
"g": [
  [1, "오늘", "g81b62f7d201a"],
  [1, "~할 수 있다", "g4a62e125cd90"],
  [1, "나는", "g19a87bc62ae1"]
]
```

id는 언어 모델이 만들지 않는다. `gloss_draft.jsonl`과 `gloss_overrides.jsonl`은 지금처럼 두 칸짜리 의미 데이터로 남긴다. 결정론적인 Python 코드가 `06_merge.py`에서 유효한 주석을 확정한 뒤 세 번째 칸을 붙인다. 그러면 `07_audio.py`와 `08_site.py`는 같은 완성 데이터를 읽을 뿐이고, id 계산법을 세 군데에 복제하지 않는다.

타입과 화면 쪽 변화의 중심은 다음 정도다.

```ts
export interface Sentence {
  de: string;
  ko: string;
  en?: string;
  /** [낱말 수, 문맥 뜻, 독일어 표현 오디오 id]. */
  g?: Array<[number, string, string]>;
}

export interface GlossPart {
  de: string;
  ko: string;
  audioId: string;
  parts: SentencePart[];
}
```

기존 두 칸 데이터를 잠시 허용하는 하위 호환은 가능하지만 길게 끌 이유는 없다. 이 저장소는 JSON과 앱을 한 번에 배포한다. 병합 단계가 세 칸을 보장하고, 타입과 검증도 세 칸을 요구하는 편이 “버튼은 있는데 소리가 없음”이라는 반쪽 상태를 빨리 잡는다.

## 링크를 예쁘게 숨기는 것이 아니라 버튼으로 바꾼다

현재 `Examples.svelte`는 쌍 안의 독일어 낱말마다 링크를 만든다. 한 쌍이 `geht es / 지내다`처럼 둘을 묶어도 위쪽에는 링크 두 개가 생긴다. 현재 카드의 단어는 링크조차 아니어서 같은 문장 안에서도 어떤 말은 눌리고 어떤 말은 눌리지 않는다.

새 동작의 최소 단위는 내부 낱말이 아니라 바깥의 `ex-gloss-pair`다. 링크와 `onWord` 호출을 없애고, 쌍 전체를 버튼으로 만든다. 독일어든 한국어든 빈 곳이든 같은 쌍 안을 누르면 같은 소리가 난다.

```svelte
<button
  class:on={playingId === `gloss/${group.audioId}`}
  class="ex-gloss-pair"
  type="button"
  aria-label={`${group.de}, 발음 듣기`}
  aria-pressed={playingId === `gloss/${group.audioId}`}
  onclick={(event) => onPlay(`gloss/${group.audioId}`, event.currentTarget)}
>
  <span class="ex-gloss-de">{group.de}</span>
  <span class:veiled class="ex-gloss-ko">{group.ko}</span>
</button>
```

실제 구현에서는 현재 단어의 붉은 강조를 보존해야 하므로 `group.de`를 통째로 출력하지 않고 기존 `group.parts`를 평문 `span`으로 그리면 된다. 중요한 것은 그 안에 `<a>`가 더는 없다는 점이다. `<button>` 안에 링크나 다른 버튼을 넣으면 HTML 자체가 잘못되므로 상세 이동 장치를 안쪽에 남겨서는 안 된다.

밑줄도 걷어 낸다. 밑줄은 여전히 링크를 약속한다. 대신 마우스를 올리거나 키보드 포커스를 받았을 때 쌍의 배경을 아주 옅게 바꾸고, 재생 중에는 독일어를 강조한다. 모바일에서는 hover가 없으므로 누르는 동안의 `:active`와 재생 중 `.on`이 피드백을 맡는다. `aria-label`에는 한국어 뜻보다 실제로 읽힐 독일어를 넣는다.

앱의 `play()`는 이미 `audio/${id}.mp3`를 재생하므로 `gloss/g….mp3`라는 상대 키를 받아도 동작한다. 다만 짧은 쌍을 빠르게 연속해서 누를 일이 많아진다. 새 `src`를 넣는 도중 앞 파일의 `pause` 이벤트가 늦게 와서 새 `playingId`를 지우지 않도록, 요청한 키와 현재 키가 같을 때만 실패·종료 상태를 정리해야 한다. 같은 쌍을 다시 누르면 현재처럼 일시정지하고, 다른 쌍을 누르면 곧바로 새 발음으로 교체한다.

문장 왼쪽의 ▶ 버튼은 남긴다. 그 버튼을 없애면 낱말은 들을 수 있지만 문장의 강세와 억양은 잃는다. 반대로 쌍을 누른 뒤 상세 카드로 갈 길은 사라진다. 이것은 우연한 손실이 아니라 이번 결정의 내용이다. 상세 탐색은 단어장 검색과 현재 카드가 담당하고, 예문은 읽고 듣는 곳으로 역할을 좁힌다.

## 오디오 단계 하나를 늘리지 않아도 된다

현재 7단계는 이미 Piper 모델을 한 번 올린 뒤 작업 목록을 순회한다. 여기에 세 번째 종류를 보태는 것이 새 스크립트를 만드는 것보다 낫다.

```python
if only in ("all", "glosses"):
    for audio_id, spoken in unique_gloss_audio(sentences, levels):
        yield f"gloss/{audio_id}", spoken, (gloss_scale,)
```

단어 파일은 보통·느린 속도를 이어 두 번 읽지만, 쌍 파일은 한 번만 읽어야 한다. 사용자는 문장을 읽다가 작은 조각을 확인하는 중이다. 같은 조각이 두 번 나오면 다음 쌍으로 넘어가는 리듬이 끊긴다. 시작값은 단어의 첫 읽기와 같은 `length_scale=1.25`가 합리적이다. 대표 표본을 휴대폰에서 들어 보고 1.25와 1.4 가운데 고르면 된다. 여러 낱말 쌍도 문장용 1.6보다 약간 빠른 편이 표현의 결합을 보존한다.

현재 A1 MP3의 단어 파일 평균은 약 9.7KB다. 이 파일은 같은 단어를 두 속도로 읽으므로, 한 번만 읽는 쌍 파일은 대체로 그보다 작을 것이다. 그래도 평균 9.7KB를 그대로 적용한 보수적인 상한은 2,510개에 약 24MB다. 실제 예상은 이보다 작지만 보고서에서 추측값을 확정값처럼 쓰지 않는다. 먼저 자주 나오는 단일어, 긴 단일어, 두 낱말 표현을 섞은 100개를 합성해 총 바이트와 탭 후 재생 지연을 잰 뒤 전체 값을 갱신해야 한다.

여기서 이미 고쳐야 할 숫자도 드러난다. `Stats.svelte`는 “A1 오디오 3,264개는 약 26 MB”라고 고정해 두었지만 디스크의 실제 payload는 현재 36.3MB다. 파일 시스템 사용량으로는 약 41MiB다. 쌍 오디오를 더하면서 문구에 새 숫자를 또 손으로 박아 넣지 말고, 사이트 빌드가 파일 수와 바이트를 `levels.json`에 기록하게 해야 한다.

오프라인 다운로드 목록에도 `gloss/` 파일을 넣는다. 현재는 단어 id와 문장 id만 모은다.

```ts
const urls = words.map((word) => `audio/${word.id}.mp3`)
  .concat(Object.keys(sentences).map((id) => `audio/${id}.mp3`))
  .concat(uniqueGlossIds(sentences).map((id) => `audio/gloss/${id}.mp3`));
```

여기서도 14,850개 URL을 그대로 넣지 않고 `Set`으로 2,510개를 만든다. 서비스 워커는 경로가 `.mp3`로 끝나는 모든 요청을 이미 오디오 캐시에 넣으므로 fetch 로직은 바꿀 필요가 없다. 내용 기반 id를 쓰면 오디오 캐시 버전을 수동으로 올릴 필요도 줄어든다.

## 158개 문장은 먼저 정직하게 남겨 둔다

A1 전체 2,585문장 가운데 158개에는 아직 문맥 주석이 없다. A2와 B1에는 아직 하나도 없다. 쌍 데이터가 없으면 쌍 발음도 만들 수 없다. 이 빈 곳에서 예전 링크를 계속 살려 두면 같은 예문 목록에서 어떤 단어는 사전을 열고 어떤 단어는 소리를 내는 두 문법이 공존한다.

주석 없는 fallback에서는 낱말 링크를 제거하고 문장을 평문으로 보여 주는 편이 낫다. 왼쪽의 문장 재생은 그대로 쓸 수 있다. A1의 158문장에 주석을 채운 뒤에는 모두 쌍 발음을 갖게 된다. A2와 B1은 문맥 주석을 만드는 시점에 같은 파이프라인으로 오디오가 자연스럽게 따라온다. 소리가 없을 때 브라우저 TTS로 몰래 대신 읽게 해서는 안 된다. OS마다 목소리와 속도가 달라지고, 오프라인 품질도 보장하지 못해 데이터셋의 일관성이 깨진다.

## 구현 순서는 소리 없는 버튼이 생기지 않게 정한다

1. Python 공용 모듈에 주석 범위 추출, 발음 문자열 정규화, 내용 기반 id, 충돌 검사를 만든다. 같은 문자열은 같은 id가 되고 `Weg`와 `weg`는 다른 id가 되는 단위 테스트를 먼저 둔다.
2. `06_merge.py`가 유효한 모든 `g`에 오디오 id를 붙이게 한다. span 합 검증 뒤에만 id를 만들고, 최종 `sentences.json`에는 세 칸짜리 튜플만 허용한다.
3. 대표 100개를 `--only glosses --limit 100`으로 합성한다. 1.25와 1.4의 명료도, 총 크기, 첫 재생 지연을 비교한 뒤 속도를 고정한다.
4. `07_audio.py`가 등급별 고유 발음만 `data/audio/gloss/`에 만든다. 기존 파일 건너뛰기와 임시 WAV를 원자적으로 MP3로 바꾸는 성질은 그대로 쓴다.
5. `08_site.py`가 그 등급의 JSON이 실제 참조하는 쌍 파일만 `app/audio/gloss/`로 하드링크한다. 하나라도 없으면 경고로 끝내지 않고 사이트 빌드를 실패시킨다. 눌리는 버튼과 없는 파일을 함께 배포하는 것보다 배포를 멈추는 편이 낫다.
6. `Examples.svelte`에서 내부 링크를 없애고 쌍 전체를 재생 버튼으로 바꾼다. 현재 단어 강조, 뜻 가리기, 문장 전체 재생은 보존한다. 주석 없는 문장은 평문으로 만든다.
7. `Stats.svelte`의 오프라인 목록에 중복 제거한 쌍 오디오를 더하고, 고정된 26MB 문구를 빌드 메타데이터로 교체한다.
8. 타입 검사와 기존 테스트 뒤, 320px 휴대폰에서 빠른 연속 탭, 같은 쌍의 정지, 문장 재생에서 쌍 재생으로 전환, 오프라인 모드를 직접 확인한다.

## 완료는 클릭 이벤트가 바뀐 것으로 재지 않는다

| 항목 | 합격선 |
|---|---|
| 발화 일치 | 모든 버튼이 화면의 독일어 표현만 읽음; 표제어로 바뀌어 읽는 사례 0 |
| 데이터 완결성 | 배포 JSON의 모든 `g`에 오디오 id가 있고 대응 MP3 누락 0 |
| 중복 | 같은 profile과 같은 대소문자 보존 발음 문자열은 파일 하나만 가짐 |
| 조작 | 쌍 어디를 눌러도 재생, 다시 누르면 정지, 다른 쌍을 누르면 즉시 교체 |
| 의미 보존 | 뜻 가리기와 현재 학습 단어 강조가 전과 같음 |
| 링크 제거 | 주석이 있는 예문 안에 단어 상세 `<a>`가 0개 |
| 접근성 | Tab으로 모든 쌍에 도달하고, 포커스가 보이며, 스크린리더가 독일어 발화 대상을 읽음 |
| 오프라인 | “전부 내려받기” 뒤 네트워크를 끊어도 문장·단어·쌍 오디오가 모두 재생됨 |
| 회귀 | Python 테스트, `npm test`, `npm run check`, `npm run build` 통과 |

여기에 발음 품질 표본 검수가 하나 더 필요하다. 단일어 30개, 활용형 20개, 여러 낱말 쌍 20개, 숫자·약어·외래어처럼 TTS가 틀리기 쉬운 표현 30개를 듣는다. 자동 합성이 부정확한 표현은 전체 음성을 다시 만들지 않고 `gloss_audio_overrides.tsv`에 `spoken` 또는 수동 MP3 경로를 적어 덮을 수 있게 한다. 자동화가 99%를 맡더라도 마지막 1%의 출구는 데이터에 있어야 한다.

## 예문은 이제 세 층으로 들린다

이 앱은 이미 단어 카드의 표제어와 예문 전체를 읽는다. 빠져 있던 것은 그 사이였다. 행간 주석을 도입하면서 화면에는 *Ich / 저는*, *bin / 있다*, *im Büro / 사무실에서*라는 의미 단위가 생겼지만, 소리는 여전히 가장 작은 표제어 아니면 가장 큰 문장뿐이었다.

새 MP3는 그 가운데 층을 채운다. 물리 파일은 쌍마다 복제하지 않고 고유 표현마다 한 번 만든다. id는 문장 위치가 아니라 발음 내용과 렌더링 설정에서 나오며, 앱은 그것을 계산하지 않고 데이터가 준 주소를 재생한다. 링크를 없앤 자리에 링크처럼 보이는 밑줄을 남기지도 않는다.

그 결과 탭의 의미가 단순해진다. 큰 ▶는 문장을 듣는다. 작은 단어쌍은 그 표현을 듣는다. 상세 카드는 단어장에서 찾는다. 화면에 세 역할이 섞이지 않으면, 학습자는 더 적게 이동하고 더 많이 듣는다. ■
