# 이름은 데이터가 정한다

## 오디오 합성기를 파이프라인에 붙이려다 알게 된 것. 파일명을 텍스트에서 만들면 예문 39쌍이 조용히 서로를 덮어쓴다. 그리고 예문에도 소리와 뜻을 달기로 했다

2026년 9월 9일 오후 11시 12분 | 14 min read

`construct_dataset/` 아래에는 지금 두 덩어리가 따로 산다. 하나는 단어 3,005개에 발음 기호와 한국어 뜻을 붙이는 네 단계짜리 파이프라인이고, 다른 하나는 독일어를 오디오로 바꾸는 `tts_poc/`다. 둘은 같은 프로젝트를 위해 만들어졌지만 서로를 모른다. 가상환경도 둘, 의존성 파일도 둘이다.

붙이는 일은 간단해 보였다. `words.json`을 읽어 `synth.py`에 단어를 넘기면 되는 것 아닌가. 그렇게 되지 않는다. 두 덩어리가 같은 단어에 서로 다른 이름을 붙이기 때문이다. 그리고 그 사실은, 예문에도 소리와 뜻을 달겠다는 세 번째 요구가 들어오는 순간 조용한 버그에서 시끄러운 버그로 바뀐다.

## 57.6퍼센트가 어긋난다

파이프라인은 항목마다 id를 만든다. *der Vater*는 `vater`다. 관사를 떼고 어간만 남기고 움라우트를 풀고 소문자로 내린다. `tts_poc`도 이름을 만든다. 같은 단어가 `der_vater`가 된다. 관사를 남기고 밑줄로 잇는다.

| 표제어 | `words.json`의 id | `tts_poc`이 만드는 파일명 |
|---|---|---|
| abholen | `abholen` | `abholen` |
| der Vater | `vater` | `der_vater` |
| die Straße | `strasse` | `die_strasse` |
| das Frühstück | `fruehstueck` | `das_fruehstueck` |
| die E-Mail | `e-mail` | `die_e_mail` |
| der (Back-)Ofen | `backofen` | `der_back_ofen` |

3,005개 중 1,731개, 57.6퍼센트가 어긋난다. 앱이 `vater.mp3`를 찾으면 없다. 이것은 그나마 나은 종류의 고장이다. 소리가 안 나면 바로 안다.

나쁜 종류는 따로 있다. `tts_poc`의 규칙에서는 단어 두 쌍이 같은 이름으로 떨어진다. `sich freuen`과 `(sich) freuen`이 둘 다 `sich_freuen`이 되고, `ein paar`와 `(ein) paar`도 그렇다. 나중에 만든 파일이 앞의 것을 덮는다. 소리는 정상으로 나고, 다만 다른 단어의 소리다. `words.json`의 id 3,005개에는 충돌이 하나도 없다.

## 예문에서는 39쌍이 겹친다

세 번째 요구를 여기에 얹으면 문제가 커진다. 독일어 문장을 보고 소리와 한국어 뜻을 확인하는 것. 지금 데이터에 예문은 6,580개, 중복을 걷어내면 6,417개다.

문장에 `tts_poc`의 규칙을 적용하면 39쌍이 같은 파일명으로 떨어진다. 원인은 하나다. 문장부호를 전부 버리기 때문이다.

```
auf_wiedersehen.mp3          ← Auf Wiedersehen!
                             ← Auf Wiedersehen.
bitte_schliessen_sie_die_tuer.mp3   ← Bitte schließen Sie die Tür.
                                    ← Bitte, schließen Sie die Tür.
alter_26_jahre.mp3           ← Alter: 26 Jahre
                             ← Alter: 26 Jahre.
```

단어에서라면 문장부호를 버려도 큰 손해가 아니다. 문장에서는 다르다. 느낌표와 마침표는 합성기에 서로 다른 억양을 지시하고, Piper는 실제로 다르게 읽는다. 즉 이 39쌍은 서로 다른 소리를 내야 하는데 한 파일을 나눠 갖는다. 학습자는 마침표로 끝나는 문장을 눌렀는데 느낌표 억양을 듣는다. 아무도 버그 신고를 하지 않을 종류의 버그다.

여기서 규칙이 하나 나온다. **이름은 데이터셋이 정하고, 합성기는 받아 쓴다.** 합성기가 텍스트를 보고 이름을 지어내는 한, 이름 규칙은 두 곳에 존재하고 두 곳은 반드시 어긋난다. 이미 어긋나 있다.

문장의 id는 슬러그가 아니라 원문의 해시로 만든다. 문장부호 하나가 달라도 다른 id가 나오고, 가장 긴 142자짜리 예문도 파일명은 열한 자다. 사람이 읽을 수 없다는 단점은 있지만, 문장 파일명은 애초에 사람이 읽을 물건이 아니다.

## 그래서 어떻게 붙이나

`tts_poc/synth.py` 197줄 가운데 파이프라인이 필요로 하는 것은 넷뿐이다. 음성 모델을 준비하는 함수, 한 속도로 읽는 함수, PCM을 wav로 쓰는 함수, wav를 mp3로 바꾸는 함수. 나머지는 인자 파싱과 출력 문구와 슬러그다.

그러니 쪼갠다. 셋으로.

```
scripts/piper_tts.py    합성 라이브러리. argv도 print도 없다
scripts/05_audio.py     5단계. words.json·sentences.json → data/audio/{id}.mp3
tts_poc/synth.py        아무 독일어나 즉석에서 들어 보는 도구. 위 라이브러리를 import 한다
```

`tts_poc`을 지우지 않는 이유가 있다. *Geschwindigkeitsbegrenzung*을 지금 당장 들어 보고 싶을 때, 파이프라인을 통과시킬 필요는 없어야 한다. 그 쓸모는 진짜다. 다만 그 도구가 만드는 파일명은 `out/`에만 살고 앱은 쳐다보지 않는다. 슬러그는 남되 권한을 잃는다.

5단계가 하는 일은 이 정도다. 이름은 받아서 쓰고, 지어내지 않는다.

```python
def work_items(words, sentences, levels):
    """(id, 읽을 텍스트, 두 번 읽을지) 목록. id 는 데이터셋이 이미 정한 것이다."""
    for w in words:
        if w["level"].lower() in levels:
            yield w["id"], w["lemma"], True      # 단어는 보통 속도 + 느린 속도
    for s in sentences:
        if s["level"].lower() in levels:
            yield s["id"], s["de"], False        # 문장은 한 번만
```

단어는 `lemma`를 읽힌다. `de`가 아니라. *der (Back-)Ofen*을 그대로 넘기면 합성기가 괄호를 읽으려 든다. 화면에는 원래 표기를 보여 주고 소리는 어간만 낸다.

가상환경은 합치지 않는다. `tts_poc/.venv`는 269 MB이고 그중 대부분이 onnxruntime이다. 파이프라인 쪽 `.venv`는 29 MB다. 단어 목록을 파싱할 때마다 300 MB짜리 환경을 짊어질 이유가 없다. `requirements-audio.txt`를 따로 두고 `make audio`가 필요할 때 설치한다.

## 가장 아름다운 리팩토링은 하지 않은 리팩토링이다

두 번째 주제로 넘어간다. 지금 코드를 어떻게 정리하는 것이 좋은가.

유혹은 분명하다. 스크립트가 다섯 개가 되고 총 1,070줄이 되었으니 슬슬 구조를 잡을 때가 된 것 아닌가. 공통 기반 클래스를 두고, 단계를 플러그인으로 만들고, 경로를 설정 파일로 빼고.

전부 하지 않는 편이 낫다고 본다. 기준은 하나다. **두 번째 호출자가 나타난 곳만 자른다.** 아직 한 번만 쓰이는 것은 아무리 길어도 그대로 둔다.

이 기준을 지금 코드에 대면 잘라야 할 곳이 정확히 셋 나온다.

**첫째, id 만드는 규칙.** 이미 두 곳에 서로 다르게 구현되어 있고 그래서 57.6퍼센트가 어긋났다. 이건 취향 문제가 아니라 버그다. 한 곳으로 옮긴다.

**둘째, 언어 모델 호출 장치.** `03_ko.py` 246줄을 성격별로 나눠 보면 이렇다.

| 부분 | 줄 수 | 예문 번역에 다시 쓰이나 |
|---|---|---|
| 프롬프트·스키마·항목 모양 | 65 | 아니오. 새로 쓴다 |
| 백엔드·묶음·재시도 | 58 | 그대로 |
| 임포트·인자·main | 123 | 대부분 그대로 |

예문 번역 스크립트를 지금 방식대로 쓰면 181줄을 복사하게 된다. 그 순간 두 파일에 같은 재시도 로직이 생기고, 한쪽만 고치는 날이 온다. 그러니 기계장치를 `scripts/llm.py`로 빼고 각 단계는 프롬프트와 스키마와 "항목 하나를 어떻게 JSON으로 만들 것인가"만 갖는다. 65줄짜리 파일 두 개가 남는다.

**셋째, Piper 합성.** 위에서 이미 말한 그것이다.

반대로 손대지 않을 곳도 분명히 해 두는 편이 좋다. `04_merge.py`의 `main()`은 83줄짜리 한 덩어리다. 길다. 그러나 그 길이는 정직하다. 병합 규칙이 그만큼 있기 때문이고, 위에서 아래로 한 번 읽으면 규칙 전부가 보인다. 이것을 `Merger` 클래스와 `apply_overrides`와 `check_plural` 따위로 쪼개면 규칙 수는 그대로인데 파일 사이를 오가야 한다. 호출자가 하나뿐인 코드를 쪼개는 것은 정리가 아니라 흩뿌리기다.

`common.py`의 경로 상수도 그대로 둔다. 산출물이 늘면 상수가 는다. 5단계와 6단계를 더하면 상수 세 줄이 는다. 세 줄을 아끼려고 설정 체계를 들이는 것은 남는 장사가 아니다.

정리하면 이런 모양이 된다.

```
scripts/
├── common.py        경로와 입출력            (그대로)
├── ids.py           id 규칙 한 곳            (새로, 두 곳에서 모음)
├── llm.py           백엔드·묶음·재시도       (새로, 03에서 빼냄)
├── piper_tts.py     합성 라이브러리          (새로, tts_poc에서 빼냄)
├── 01_wordlist.py   TSV → wordlist.jsonl
├── 02_ipa.py        덤프 → ipa.jsonl
├── 03_ko.py         단어 뜻                  (프롬프트만 남음)
├── 04_sentences.py  예문 번역                (새로, llm.py 사용)
├── 05_merge.py      → words.json, sentences.json
└── 06_audio.py      → data/audio/{id}.mp3    (새로, piper_tts.py 사용)
```

새 파일 다섯 중 셋은 기존 코드를 옮겨 담은 것이다. 처음부터 쓰는 것은 예문 번역 단계 하나이고, 오디오 단계는 위의 `work_items` 정도에 라이브러리 호출을 붙인 얇은 껍데기다. 이것이 이 프로젝트가 지금 감당할 만한 구조 변경의 전부다.

## 1,070줄 가운데 읽어야 할 것은 102줄이다

구조 이야기를 했으니 그 구조 안에서 무엇을 실제로 읽어야 하는지도 말해 두는 편이 낫다. `construct_dataset/`의 파이썬은 다 합쳐 1,070줄이다. 전부 읽을 필요는 없고, 읽어서도 안 된다. 대부분은 지루한 문자열 처리이거나 인자 파싱이다.

판단이 들어 있는 곳, 그러니까 한 줄을 바꾸면 데이터 수천 개가 조용히 달라지는 곳은 다섯 군데뿐이다.

| 위치 | 줄 | 무엇이 걸려 있나 |
|---|---|---|
| `01_wordlist.py:37-97` | 61 | 독일어 형태론이 코드가 된 유일한 자리. 복수형 1,032개가 여기서 나온다 |
| `01_wordlist.py:128-131` | 4 | 모든 단어 id의 출처. 이 보고서의 주제 |
| `tts_poc/synth.py:41-45` | 5 | 두 번째 이름 규칙. 57.6퍼센트 어긋남과 39쌍 충돌의 원인 |
| `02_ipa.py:98-112` | 15 | 동음이의 페이지 중 무엇을 고를지. 점수 하나가 IPA 커버리지를 움직인다 |
| `03_ko.py:39-55` | 17 | 한국어 뜻 3,005개의 품질이 이 프롬프트에서 나온다 |

이 다섯 조각을 나란히 읽으면 파이프라인이 내리는 결정 전부가 보인다. 나머지 968줄은 그 결정을 실행하는 배관이다.

배관 중에도 한 번쯤 볼 만한 것이 둘 있다. `02_ipa.py:62-88`은 2.8 GB를 8초에 훑는 요령이고, 한 번 이해하면 다시 볼 일이 없다. `04_merge.py:27-109`는 병합 규칙 전부이고, `words.json`이 이상할 때만 열면 된다.

읽지 않아도 되는 것은 분명히 해 두는 편이 도움이 된다. `01_wordlist.py:134-234`는 괴테 목록의 표기 변덕을 하나씩 벗겨 내는 101줄인데, 여기가 맞는지는 사람이 눈으로 보는 대신 스무 개짜리 복수형 표본이 확인한다. 1·2·3단계 `main()`을 더한 150줄은 인자 파싱과 진행 로그다. `tts_poc/synth.py:106-197`은 CLI 껍데기이고, 위 계획대로라면 곧 `tools/say.py`로 옮겨 가며 대부분 사라진다.

## 예문에 뜻을 다는 값

세 번째 주제. 예문 6,417개에 한국어 뜻을 달면 얼마나 걸리고 얼마가 드나. 60개를 실제로 돌려 재 봤다.

첫 측정은 실망스러웠다. 60문장에 116초, 정가 $0.147. 6,417개로 환산하면 3시간 반에 $15.74다. 출력 토큰이 12,029개였다. 짧은 한국어 문장 60개를 쓰는 데 그만한 토큰이 나올 리 없으니, 대부분은 모델이 답을 내기 전에 생각한 몫이다.

그래서 `--effort low`를 줬다.

| 설정 | 60문장 소요 | 출력 토큰 | 비용 | 6,417개 환산 |
|---|---|---|---|---|
| 기본 | 116.0초 | 12,029 | $0.147 | 207분 / $15.74 |
| `--effort low` | 31.9초 | 2,491 | $0.052 | 57분 / $5.53 |

3.6배 빠르고 2.8배 싸다. 다만 결과를 읽어 보니 품질이 흔들렸다.

```
기본        내일부터 일해야 해요.        /  제 형은 가끔 저희를 찾아와요.
effort low  내일부터 나는 일해야 해.     /  내 형(오빠/남동생)은 가끔 우리를 방문해.
```

존댓말이 반말로 바뀌고 괄호로 대안을 나열한다. 여기서 모델을 탓하고 effort를 되돌리는 것이 자연스러운 반응이지만, 프롬프트를 다시 읽어 보니 내가 틀렸다. 나는 이렇게 적어 두었다.

> 존댓말 여부는 원문을 따른다. Sie면 존댓말, du면 반말.

*Ab morgen muss ich arbeiten*에는 Sie도 du도 없다. 규칙이 답을 주지 않는 문장이고, 이런 문장이 예문의 상당수다. 높은 effort의 모델은 빈틈을 알아서 메웠고 낮은 effort의 모델은 메우지 않았다. 품질 차이가 아니라 빈틈이 드러난 것이다. 규칙을 이렇게 고쳤다.

```
- 말투는 해요체로 통일한다. 원문에 du가 있을 때만 반말로 쓴다.
  Sie도 이름 부르기도 없는 평서문은 해요체다.
- 괄호로 대안을 나열하지 않는다. Bruder는 문맥이 없으면 '형제'가 아니라 하나를 골라 '형'으로 쓴다.
```

같은 `--effort low`로 다시 돌린 결과다.

```
내일부터 일해야 해요.
함부르크부터는 여행 요금이 200유로예요.
다음 주부터 저희 가게는 토요일마다 문을 닫아요.
형은 가끔 우리를 방문해요.
```

기본 effort와 구별되지 않는다. 30.9초, $0.052. **effort를 낮추는 것이 품질을 깎은 게 아니라, 프롬프트의 빈틈을 드러냈다.** 빈틈을 막고 나니 낮은 effort로도 같은 답이 나온다. 순서를 뒤집어 말하면, 비싼 모델의 여유는 프롬프트가 덜 쓰인 것을 가려 주는 데 쓰이고 있었다.

묶음 넷을 동시에 보내면 6,417개에 14분, $5.53이다. 지난번 단어 3,005개는 기본 effort로 돌렸으니, 같은 손질을 하면 거기서도 시간과 돈이 남는다.

## 소리는 137 메가바이트다

오디오 쪽 계산이 남았다. 문장 30개를 실제로 합성해 쟀다. 문장 하나에 0.248초, mp3 64k로 평균 14 KB다. 단어는 앞 보고서에서 두 속도 합쳐 0.35초, 17 KB였다.

| | 개수 | 합성 시간 | mp3 64k |
|---|---|---|---|
| 단어 (두 속도) | 3,005 | 17.5분 | 49.9 MB |
| 예문 (한 속도) | 6,417 | 26.5분 | 87.7 MB |
| 합계 | 9,422 | 44.1분 | 137.6 MB |

만드는 데 44분은 문제가 아니다. 한 번 만들면 끝이고 노트북은 밤에 논다. 137 MB가 문제다. 정적 호스팅 한도에는 들어가지만, 휴대폰이 오프라인용으로 통째로 받아 두기에는 부담스럽다. 앞 보고서가 22 MB를 예상한 것은 단어 1,300개만 셌기 때문이고, 지금은 단어가 3,005개에 예문이 6,417개다.

두 가지로 줄인다.

**비트레이트.** 같은 문장 하나를 다시 인코딩해 봤다.

| 인코딩 | 크기 | 137 MB 환산 |
|---|---|---|
| mp3 64k (현재) | 12,164 B | 137.6 MB |
| mp3 32k | 6,183 B | 70.0 MB |
| opus 24k | 4,342 B | 49.1 MB |

말소리 하나짜리 모노 오디오에 64k는 과하다. opus가 가장 작지만 사파리의 Ogg Opus 지원이 늦게 들어온 편이라 실제 기기에서 확인이 필요하다. 확인 전까지는 mp3 32k가 안전한 선택이고, 그것만으로 절반이 된다.

**등급별로 나누기.** 더 중요한 쪽은 이것이다. 앱은 A1부터 돈다. A1이 쓰는 오디오만 먼저 만들어 배포하면 된다.

| 등급 | 단어 | 새 예문 | mp3 32k | opus 24k |
|---|---|---|---|---|
| A1 | 679 | 2,585 | 23.7 MB | 16.6 MB |
| A2 | 607 | 1,639 | 16.5 MB | 11.6 MB |
| B1 | 1,719 | 2,193 | 29.7 MB | 20.9 MB |

A1만 23.7 MB다. 휴대폰이 받아 둘 만하고, 앞 보고서의 22 MB 예상과 거의 같은 자리에 떨어진다. A2와 B1은 학습자가 그 등급에 닿을 때 받으면 된다. 5단계에 `--levels a1`을 두는 이유가 여기 있고, 그것이 위 `work_items`가 등급을 거르는 이유다.

## 그래서 다음에 할 일

세 주제가 한 자리로 모인다. 예문에 소리와 뜻을 달겠다는 요구가 오디오 합성기를 파이프라인에 정식으로 들이도록 강제하고, 그 과정에서 이름 규칙이 두 벌이라는 사실이 드러나며, 그 두 곳을 한 곳으로 모으는 것이 지금 필요한 리팩토링의 전부다. 순서는 이렇다.

1. `ids.py`를 만들어 id 규칙을 한 곳에 모은다. 문장은 해시, 단어는 지금 규칙 그대로.
2. `llm.py`를 `03_ko.py`에서 빼낸다. 프롬프트만 남긴다.
3. `04_sentences.py`를 쓴다. `--effort low`와 보강한 프롬프트로. 14분, $5.53.
4. `piper_tts.py`를 `tts_poc/synth.py`에서 빼내고 `06_audio.py`를 쓴다. 이름은 받아 쓴다.
5. A1부터 만든다. mp3 32k로 23.7 MB.

`04_merge.py`의 긴 `main()`은 그대로 둔다. 손댈 이유가 아직 없다. ■

### id 규칙을 한 곳으로 모으면

지금 두 곳에 흩어져 있는 것을 합치면 이런 모양이 된다. 단어 규칙은 `01_wordlist.py`의 것을 그대로 옮기고, 문장 규칙만 새로 더한다.

```python
"""id 규칙. 데이터셋의 모든 이름이 여기서 나온다.

단어는 사람이 읽을 수 있어야 하므로 슬러그, 문장은 문장부호까지 구별해야 하므로 해시.
슬러그를 문장에 쓰면 39쌍이 충돌한다. 'Auf Wiedersehen!' 과 'Auf Wiedersehen.' 이 한 파일이 된다.
"""
import hashlib, re, unicodedata

ASCII = str.maketrans({"ä": "ae", "ö": "oe", "ü": "ue", "Ä": "ae", "Ö": "oe", "Ü": "ue", "ß": "ss"})


def word_id(lemma: str) -> str:
    """'Vater' → 'vater'. 같은 lemma 가 겹치면 부르는 쪽에서 -2 를 붙인다."""
    t = unicodedata.normalize("NFKD", lemma.translate(ASCII)).encode("ascii", "ignore").decode()
    return re.sub(r"[^a-z0-9]+", "-", t.lower()).strip("-") or "x"


def sentence_id(de: str) -> str:
    """원문 그대로 해시한다. 문장부호도, 대소문자도, 공백도 구별에 쓴다."""
    return "s" + hashlib.sha1(de.encode("utf-8")).hexdigest()[:10]
```
